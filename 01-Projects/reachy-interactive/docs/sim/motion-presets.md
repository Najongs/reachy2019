# 동작 프리셋 학습 (모션 분기)

아래는 시각 서보 파이프라인([pipeline.md](pipeline.md)) 이전부터 있던
**키프레임 동작 학습** 분기다. 명령 문장 -> opus 동작 JSON -> 로컬 채점
-> 비평 반복 -> 프리셋 채택의 흐름으로, 지금도 쓴다.

## 시뮬레이션으로 동작을 스스로 다듬는다

```
말 만들기(ollama, 무료) ──▶ 동작 설계(opus) ──▶ 시뮬 실행 + 채점(로컬 CPU)
                                  ▲                        │
                                  └──── 지적 + 궤적 그림 ────┘
```

```bash
# [DGX] 상황과 발화 만들어 보기 (로컬 모델, 공짜)
python3 sim/sim_scenarios.py --personas 4 --per-persona 6

# [DGX] 자동으로 만들고, 돌려 보고, 고치기  (opus 호출 = 과제수 × (1+fix))
python3 sim/sim_train.py --rounds 5 --fix-rounds 2 --token reachy2019

# [DGX] 특정 동작만 채점해 보기
python3 sim/sim_eval.py --preset wave --render /tmp/wave.png
python3 sim/sim_eval.py --all-presets

# [로봇] 학습된 후보를 눈으로 보고 프리셋으로 채택
python3 sim_play.py --candidates      # 뷰어: ws://<Pi IP>:6172
```

**역할을 셋으로 나눈다.**

| | 맡는 것 | 비용 |
|---|---|---|
| opus | **무엇을** 할지 — 관절 선택, 키프레임 구성, 이야기 | 구독 호출 |
| CEM 탐색 | **얼마나** — 각도와 시간의 미세 조정 | 0회 (CPU 28ms/채점) |
| 교훈 장부 | 되풀이된 지적을 다음 설계 앞에 놓기 | 0회 |

"어깨를 3도 더 들면 점수가 오른다" 는 언어로 풀 일이 아니다. 그냥 찾으면 된다.
그래서 구조는 opus 가 잡고 숫자는 교차엔트로피법(CEM)으로 찾는다 — opus 호출을
한 번도 늘리지 않고 초안마다 **+6~16점**이 붙는다. 의미가 망가지지 않게 원래
각도에서 25도 이상 못 벗어나게 묶었다: 고쳐 쓰는 게 아니라 다듬는 것이다.

**교훈이 정책 갱신을 대신한다.** 가중치를 고치는 대신, 두 번 이상 되풀이된
지적을 말로 정리해 다음 설계 프롬프트 앞에 놓는다(`config/sim_lessons.json`).
세 번째부터는 같은 실수를 처음부터 피한다.

**손으로 쓴 프리셋도 탐색만으로 올라갔다** — 9개 전부, 평균 86.4 → 92.7
(+6.2), 25초, opus 호출 0회. antenna_dance +14, handshake +10, wave +8.
대부분 원인이 같았다: duration 을 너무 짧게 잡아 속도 상한에 걸리고 있었다.

```bash
python3 sim/sim_opt.py --preset wave --iters 12 --pop 48   # 하나만 다듬어 보기
```

### 개선 과정을 그림으로

```bash
python3 sim/sim_train.py --rounds 10 --token reachy2019   # sim_data/gallery/ 에 자동 저장
```

`sim_data/gallery/00-progress.png` 는 과제별 첫 점수와 최종 점수를 잇는 곡선,
`NN-<요청>.png` 는 그 과제의 **초안과 최종본 궤적을 위아래로 붙인 한 장**이다.
"75점 → 100점"이라고만 하면 무엇이 달라졌는지 모른다 — 박수의 경우 위에서 본
그림에서 초안은 양손이 ±0.35 로 벌어진 채이고 최종본은 몸 앞 y≈0 으로 모이는
것이 바로 보인다.

### 시연 전 위험 확인

```bash
python3 sim/sim_safety.py --all-presets                  # 프리셋 전부
python3 sim/sim_safety.py --candidates                   # 학습이 만든 후보 전부
python3 sim/sim_safety.py --preset wave --link-radius 0.032   # 잰 값으로
```

**실행기의 검증기는 팔을 굵기 없는 중심선으로만 본다.** 중심선이 금지 영역에서
5cm 떨어져 있어도 전완 반지름이 4.5cm 면 실제 공기 틈은 0.5cm 다. 그래서 여기서는
팔을 **선분의 사슬**로 보고 선분 대 선분 최단거리를 직접 풀고, 링크 두께를 뺀
표면 간격을 잰다. 시간 방향도 실행기의 10Hz 대신 100Hz 로 훑는다.

몸통 상자는 '손이 들어오면 안 되는 영역'이지 몸의 외곽선이 아니다 — 팔을 가만히
늘어뜨리기만 해도 상자 옆면에서 0.5cm 다. 그래서 몸통·머리는 절대값이 아니라
**휴식 자세보다 얼마나 더 가까워졌는가**로 본다. 두 팔 사이와 같은 팔 안쪽은
쉴 때 38cm 떨어져 있으므로 절대값이 그대로 의미가 있다.

```
안전   표면 간격 5cm 이상
주의   2~5cm — 조립 오차와 처짐을 생각하면 시연에서는 피하는 게 낫다
위험   2cm 미만 또는 파고듦
```

**팔 굵기는 3D 모델에서 잰다** (`sim/measure_arm.py`). `reachy.glb` 가
순기구학과 같은 좌표계의 휴식 자세로 되어 있어서(경계 y ±0.248 = 어깨 ±0.19 +
팔 두께, z 바닥 -0.687 = 손끝 -0.64), 링크 축 둘레 정점까지의 거리가 곧
반지름이다. 자를 댈 필요가 없었다.

```
상완 4.4cm   전완 3.7cm   손/그리퍼 4.4cm      (95 백분위, 관절 여백 5cm)
```

관절 여백이 중요하다. 2cm 로 두면 어깨 브래킷이 상완 표본에 섞여 백분위를
올릴수록 4.6 → 6.9 → 10.1cm 로 튀고, 그러면 **가만히 서 있는 자세가 '위험'
으로 나온다**. 4cm 이상 잘라내면 3.9~5.0cm 로 안정된다. 전완과 손은 어느
설정에서도 흔들리지 않는다.

이 값으로 보면 **프리셋 9개 전부 안전**이다.

학습 루프도 이 감사를 돌린다(40Hz). 안전 등급이 아니면 지적에 얹히고 점수가
깎이므로, 새로 만드는 동작은 여유를 갖고 나온다. 로봇에서
`sim_play.py --candidates` 로 재생할 때도 등급이 먼저 뜬다.

### 말과 몸이 따로 노는 것 잡기

박수·하이파이브를 opus 가 "못 한다"며 거부하길래 이유를 찾아봤다. **두 팔이
닿는 것만 금지돼 있고 가까이 가는 것은 허용된다** — `ARM_CLEARANCE` 9cm 는 손
반지름 4.4cm 두 개(8.8cm)에 딱 맞춘 값이라 접촉만 막는다. 무작위 자세 4만 개를
훑어 보니 두 손은 관절 한계상 **3.2cm 까지 접근**할 수 있고 그 자세도 금지구역
검사를 통과한다. 여유가 없어서가 아니라 규칙을 그렇게 알려 주지 않았을 뿐이었다.

`config/motion_prompt.txt` 에 근접 규칙을 실측값과 함께 적었더니 세 동작 다
100점으로 통과했다 — **그런데 말만 바뀌고 몸은 그대로였다.**

```
"하이파이브! 힘차게 마주쳐 볼게요"  ->  두 손 40.5cm (휴식 자세가 38cm)
"얼굴 좀 가릴게요"                 ->  손이 머리 중심에서 49cm
```

채점기는 역학만 보므로 만점을 줬고, 새로움 검사도 궤적이 다르니 통과시켰다.
그래서 요청이 기하학적으로 무엇을 요구하는지 아는 것들은 직접 확인한다.

| 요청 | 확인하는 것 |
|---|---|
| 박수·하이파이브·손 모으기 | 두 손이 22cm 안으로 들어왔나 |
| 얼굴·턱 가리기 | 손이 머리 중심 32cm 안으로 왔나 |
| 가리키기·내밀기 | 손이 몸 앞 x 0.30 이상 나갔나 |

어긋나면 무엇이 얼마나 모자란지 말해 주고 30점을 깎는다. 아는 요청만 보는
반쪽짜리지만, "말로는 마주친다면서 40cm 떨어져 있다"를 잡는 것이 아무것도 안
보는 것보다 낫다.

**결과** — 박수 40.5 → **13cm**, 하이파이브 → **17cm**, 얼굴 가리기 손-머리
49 → **25cm**(머리 표면에서 10cm). 전부 안전 등급. 박수의 진행이 이 구조를 잘
보여 준다: 69점 → **0점(검증기가 "두 팔이 서로 부딪힐 것 같아요"로 거부)** →
100점. 접촉까지 밀어붙였다가 안전 한계에서 튕겨 나와 13cm 로 물러섰다.

### 이름만 다른 같은 동작 걸러내기

채점기가 포화되면 - 만드는 것마다 100점이면 - 남은 구분은 '이미 있는 것과
다른가' 뿐이다. 실제로 새 동작 20개를 만들었더니 **뒤쪽 10개 중 8개가 앞쪽과
거의 같은 궤적**이었다:

```
물건을 조심스럽게 건네주는 시늉  ~  가위바위보 내밀듯이     1.3cm 차이
오른팔로 하트 그리듯 원을        ~  파도타기처럼 물결치듯    4.0cm
축하한다고 양팔 번쩍 만세        ~  기지개 켜듯이 쭉 펴봐    4.6cm
```

이름만 다르고 몸은 같은 동작이 쌓이면 시연이 지루해진다. 그래서 손끝 궤적을
24점으로 요약해 이미 가진 동작 전부와 비교하고, 8cm 안쪽이면 지적하고 20점을
깎는다. 한 번의 실행 안에서 방금 만든 것도 곧바로 비교 대상이 된다.

**채점기를 15배 빠르게 했다.** `_arm_points` 가 링크마다 FK 를 처음부터 다시
계산해(실질 O(n²)) 한 번 채점에 471ms 였다. 한 번만 훑도록 고치고, 탐색용
빠른 모드(성긴 샘플링 + 팔-팔 간섭을 직접 검사)를 더해 **28ms**가 됐다. 두
모드의 점수는 프리셋 9개에서 완전히 같다.

**시뮬레이터를 따로 만들지 않았다.** `sim_eval` 은 실물이 쓰는 검증기
(`motion_exec.validate`)와 순기구학을 그대로 빌려 쓴다. 별도 물리 엔진을 세우면
시뮬에서만 되는 동작이 나온다. 하드웨어도 GPU 도 필요 없고, ollama 가 올라간
GPU 한 장 외에는 아무것도 안 쓴다.

**무엇을 보고 채점하나**

| | 재는 것 |
|---|---|
| 안전 | 검증 통과 여부, 깎인 각도, 속도 상한 때문에 늘어난 시간 |
| 크기 | 손이 실제로 움직인 거리 (12cm 미만이면 복도에서 안 보인다) |
| 여유 | 몸통·머리·반대팔에 가장 가까이 간 거리 |
| 성격 | 방향 전환 횟수 — 손 흔들기는 왕복해야 하고 가리키기는 아니다 |
| 군더더기 | 키프레임에 넣고 한 번도 안 움직인 관절 |
| 마무리 | 마지막 자세가 휴식에서 얼마나 떨어져 있나 |

점수 하나로 줄이지 않고 **문제 목록**을 함께 준다. "손이 3cm 밖에 안
움직입니다" 가 "72점" 보다 훨씬 잘 고쳐진다. 궤적을 위/옆/앞 3면도와 관절
곡선으로 그려 함께 보여 준다 — opus 가 그림을 보고 고친다.

**손으로 쓴 프리셋의 기준선**: bow 100, hug_open 91, cheer 88, handshake 87,
point_forward 87, antenna_dance 86, greet 85, wave 82, pick_to_tray 72.

**첫 실측 결과**: "오른손 크게 흔들어서 인사해줘" 가 75점 → **100점** 으로
고쳐졌다. 사람이 쓴 `wave` 프리셋(82점, 최대 78cm, 왕복 3회)보다 나은
100cm·왕복 4회짜리가 나왔다. 90점 이상이면서 지적이 없는 것만
`config/motion_candidates.json` 에 남고, 로봇에서 `sim_play.py --candidates`
로 눈으로 보고 채택한다.

## 시뮬레이터

- `sim/sim_viewer.html`: 실물 CAD(reachy.glb) 3D 렌더. [실물](6171)/[시뮬](6172) 전환, 캘리브레이션 패널
- 전 관절 로컬 z축, 부호는 실물 대조로 확정. neck 은 gaze 방향 근사
- `sim/sim_play.py --candidates`: 생성 동작 후보를 시뮬에서 재생·채택 → 프리셋 승격
