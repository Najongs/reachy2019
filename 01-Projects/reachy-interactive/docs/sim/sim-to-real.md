# 시뮬 -> 실물 전이 로드맵

목표: 시뮬에서 학습한 다양한 동작이 검증을 거쳐 실물로 넘어가고, 실물에서
쌓인 데이터가 시뮬로 되돌아오는 양방향 순환.

## 지금 성립하는 것 (0단계)

- **기구학 동일**: 시뮬 MJCF 가 실물 검증기와 같은 `motion_exec.CHAINS`
  에서 생성된다 (FK 불일치 0.0m). "시뮬에서 안전하면 실물에서도 안전"
  의 근거. 목(Orbita)도 실물 역기구학 그대로.
- **속도 상한 대응**: 실물 목 속도 상한 = 시뮬 gaze_step_deg.

## 다리 도구 (sim_bridge.py)

```bash
python3 sim/sim_bridge.py --export   # 시뮬 -> 실물 제안
python3 sim/sim_bridge.py --absorb   # 실물 -> 시뮬 반영거리
```

**export**: 검증 배터리(다양한 높이 x 태스크, 충돌 0 필수 + 성공/품질
문턱)를 통과해야 `config/behavior_real.proposed.json` 이 만들어진다.
탈락하면 제안 자체를 안 만든다 (첫 실행에서 실제로 충돌 1로 탈락 -
문지기가 일한다는 뜻). 적용은 사람 검토 + 모터 켠 감독 시연 후.

**absorb**: 실물 로그에서 시뮬로 가져올 것을 뽑는다. 2026-09-06 기준
실물이 주는 것:
- **명령 분포** (`config/real_commands.json`): 사람들이 실제로 시키는 것
  - 만세/박수/인사/안테나 (제스처 분기 수요)
  - **"물건 보관함에 넣어 줘" 계열 3건 - pick 실수요가 있다**
- 실패 사유: null_moves 6 (opus 가 빈 동작 반환 - 프롬프트 개선거리),
  broker_failed 2 (인프라). 동작 품질 실패는 아직 0 - 모터를 켠 기간이
  짧아서다. 데이터가 쌓이면 실패 유형이 시뮬 태스크가 된다.

## 단계

| 단계 | 내용 | 상태 |
|---|---|---|
| 0 | 기구학 동일·속도 상한 대응 | 완료 |
| 1 | 행동 파라미터 export 게이트 (검증 배터리 -> 제안 -> 사람 검토) | 도구 완료, 통과 대기 |
| 2 | 실물 서보 런타임: object_vision 검출 + 브로커 접지 + motion_exec 로 Pi 에서 시뮬과 같은 폐루프 | 미착수 (다음 큰 조각) |
| 3 | 감독 시연: 모터 켠 상태, 사람 입회, 느린 배속부터 | 2 이후 |
| 4 | 실물 궤적(state_mirror 엔코더) -> 시뮬 속도·지연 보정 | 데이터 쌓이면 |
| 5 | pick: 그리퍼 폭 제어 + 파지 자세 (실수요 확인됨) | 접근축·접촉허용 준비됨 |

## 원칙

- 두 방향 모두 **제안까지만 자동**, 적용은 사람이 (proposed.json 패턴).
- 실물 첫 시연은 언제나: 감독 하에, 느리게, 작업영역 제한.
