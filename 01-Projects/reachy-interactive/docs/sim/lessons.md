# 피로 배운 원칙들

이 세션의 버그는 전부 같은 병이었다: **harness 가 현실과 안 맞는
성공/점수를 자신 있게 보고한다.** 여러 모델이 서로를 채점하는 구조에서
이건 치명적이다. 새 지표·새 판정을 만들 때마다 아래를 확인하라.

## 1. 무동작 기준선 검사

새 지표는 **아무것도 안 하는 로봇**에 먼저 적용해 본다.
- rest 자세가 "위험" 판정 (몸통 상자를 실루엣으로 오해)
- 팔꿈치 rest=0 이 관절 한계라 여유 0° 로 집계
- 잡기 시간이 속도 위반으로 집계
- look 태스크(팔 안 씀, 궤적 없음)가 품질 0 = '부자연' 판정

## 2. 공허참(0/0) 금지

빈 태스크 목록에서 `성공 0 >= 태스크 0` 은 참이다. 이게 "전원 성공"
으로 통해 래칫이 55→85 로 폭주하고 839회 공회전했다. 집계·래칫·통과
판정 앞에는 반드시 분모 > 0 가드.

## 3. 순환 정의 금지

태스크 실현가능성을 **학습 중인 파라미터**로 판정했더니, 파라미터가
나빠질수록 '가능한 태스크' 가 사라졌다. 정의(기준)는 고정된 것
(`sim_agent.DEFAULTS`)에 못박는다.

## 4. 최종 상태만 보지 말 것

최종 위치만 보면 테이블을 뚫고 지나간 경로도 '성공' 이다 (13/13 프레임
투과가 성공으로 통과했었다). 판정은 경로 전체의 최소 여유로.

## 5. 측정 잡음과 미분을 섞지 말 것

잡음 낀 측정값으로 수치 자코비안을 만들면 방향이 엉킨다. 미분은 모델
(잡음 없음)로, 잡음은 측정 오차에만.

## 6. 프로브 후 상태 복원

상태를 저장→찔러보고→정확히 복원. 복원 뒤에 측정값을 읽으면 단서가
사라진다 (크기 단서를 복원 후에 읽어 죽였던 사고).

## 7. 언어모델의 절대 점수는 흔들린다

평가 모델의 1~10 점은 호출마다 다르다. 쓰려면 (a) 비교(A/B 결투)로 바꾸거나
(b) 결정론 점수의 박빙 심판으로만. 결투가 계측을 자꾸 뒤집으면 계측
가중치를 의심하라 - 그것도 감사 신호다.

## 8. 셸 자멸 패턴 (사소하지만 세 번 겪음)

`pkill -f "패턴"` 의 패턴이 자기 명령줄에 그대로 들어 있으면 자기 셸을
죽인다. 반드시 `pgrep -f "이름[.]py"` 브래킷 트릭.

## 9. 조건부 지표는 조건이 먼저 결판난 뒤에 쓴다

품질(효율·저크·여유·시야)은 '도달한다는 전제 아래서의 잘함' 이다. 순위가
(충돌, 성공, 품질)이면 전원 실패 동률일 때 품질만 남아, 소심하게 안 가는
동작이 이긴다 - 1099회 동안 "우아하게 실패하는 법" 을 학습했다. 순위는
(충돌, 성공, **목표에 가깝게**, 품질) - 조건으로의 압력이 항상 앞선다.
평가는 진실을 말했고 개선이 듣지 않은 사고: 발산 감사(품질↑·성공↓)가
이제 이 패턴을 기계로 감시한다.
